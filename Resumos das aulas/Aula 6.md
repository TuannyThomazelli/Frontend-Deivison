# Aula 06 — Projetos Front-End

## 1. Por que gerenciar um projeto Front-End?
Projetos crescem rápido. **Sem planejamento**, aparecem:
- tarefas esquecidas;
- requisitos confusos;
- retrabalho;
- conflitos no Git;
- atrasos;
- problemas de integração;
- dificuldade para acompanhar o progresso.

**Com processo de gestão**, o projeto passa a ter:
- responsabilidades claras;
- prioridades definidas;
- entregas incrementais;
- acompanhamento do progresso;
- menos retrabalho.

## 2. Gestão de Projetos Front-End
Significa organizar pessoas, tarefas, tecnologias e prazos. As decisões precisam ser **planejadas, acompanhadas e ajustadas** para garantir entregas contínuas e alinhadas aos objetivos.

## 3. Gestão de Requisitos
O projeto começa com uma **ideia**, que vira **requisitos claros** e depois é organizada em um **backlog**. Em seguida, as atividades são priorizadas, desenvolvidas, revisadas, testadas e disponibilizadas aos usuários por um processo estruturado.

### Requisito → História → Tarefa
| Nível | Exemplo da aula |
|---|---|
| **Requisito** | O sistema deve permitir gerenciamento de tarefas |
| **User Story** | Como usuário, quero criar uma tarefa |
| **Tarefas** | Criar formulário · Criar componente · Validar campos · Integrar API · Criar testes |

## 4. Gestão do Backlog
O backlog reúne funcionalidades, melhorias, correções e outras atividades necessárias para desenvolver e evoluir o produto. Os itens recebem prioridades diferentes, permitindo concentrar os esforços inicialmente nas funcionalidades mais importantes.

## 5. Gestão de Prioridade e Estimativa
- **Priorização:** define o que desenvolver primeiro, considerando objetivos, necessidades e restrições.
- **Estimativas:** ajudam a equipe a compreender a **complexidade relativa** das atividades antes de assumir um conjunto de tarefas.

## 6. Definition of Done (DoD)
Conjunto de critérios para considerar uma tarefa **realmente concluída**. Podem incluir: código implementado, testes realizados, revisão concluída, responsividade verificada e integração realizada.

## 7. Scrum
Framework ágil para desenvolver produtos complexos de forma **incremental**, com inspeção frequente, adaptação e entregas contínuas. No Front-End, ajuda a organizar requisitos, priorizar funcionalidades, planejar **Sprints** e acompanhar o trabalho da equipe.
